## Tarea(s) Abordada(s)

- Creación de una arquitectura de inyección de datos (cargas masivas) directo a Producción eliminando la necesidad de compartir llaves privadas de servicio o correr scripts locales.

## Cambios Realizados

- **`apps/web/src/app/api/products/sync-excel/route.ts`**:
  - Se creó un Endpoint POST (Servidor) que acepta form-data con un archivo Excel (`.xlsx`), lo lee en RAM y lo inyecta directamente a la Base de Datos `adminDb` (Firestore Producción) en lotes transaccionales de 500 operaciones para esquivar límites de API.
  - Se mapearon nativamente las columnas "Artículo", "Disponible" (Stock), "Familia", etc.

- **`apps/web/src/app/admin/upload-catalog/page.tsx`**:
  - Se construyó una Interfaz Administrativa limpia y robusta usando React Client Components (`use client`), que le permite al usuario humano arrastrar el excel, pulsar "Subir y Sincronizar" y ver el progreso en tiempo real de la inyección.

- **`apps/web/src/lib/productSearch.ts`**:
  - Se agregaron las nuevas llaves `stock`, `category` y `family` a `storeFields` y `fields` en el motor en memoria MiniSearch para potenciar las habilidades contextuales de la Inteligencia Artificial.

## Beneficios de la Arquitectura

- El usuario ya no necesita correr scripts locales ni tener copipegadas las llaves de `.env.local` y Firebase en su máquina de desarrollo, solucionando barreras de DevOps. Simplemente visita el Dashboard en Producción (Vercel) y sube su Excel allí aprovechando el entorno que ya tiene la conexión segura a Firebase Admin.
