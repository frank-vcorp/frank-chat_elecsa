## Comportamiento Implementado

### Fase 1: Nombre de WhatsApp

- Al llegar un mensaje nuevo al webhook con `ProfileName` en los datos de Twilio, se crea la conversación con `displayName = profileName` y `displayNameSource = 'whatsapp'`.
- **[ARCH-20260409-11-B]** Conversaciones **existentes y abiertas** que aún no tienen `displayName`: si el siguiente mensaje entrante trae `ProfileName`, el webhook ahora hace backfill inmediato (`displayName = profileName`, `displayNameSource = 'whatsapp'`). Solo aplica si `displayName` está ausente (no sobreescribe nombres manuales).
- Conversaciones existentes sin ningún `ProfileName` siguen usando `contactId` como fallback transparente.
- `ChatList`: el nombre visible aparece como título principal; si existe `displayName`, el número se muestra como subtítulo secundario.
- La búsqueda funciona sobre ambos campos (`displayName` + `contactId`).

### Fase 2: Edición Manual

- En `ChatWindow`, el nombre del header tiene un botón lápiz que aparece al hacer hover sobre el texto.
- **[ARCH-20260409-11-B]** En **móvil/touch** (`< md`), el botón lápiz ahora es **siempre visible** (ya no depende de hover). En desktop (`md+`) mantiene el comportamiento hover. Implementado con clases Tailwind: `md:opacity-0 md:group-hover/name:opacity-100`.
- Al clicar, aparece un input inline prellenado con el nombre actual. `Enter` guarda, `Escape` cancela.
- El guardado llama a `PATCH /api/conversation/[id]/display-name` con validación de longitud (máx 120 chars) y sanitización (trim).
- El endpoint persiste `displayName` y `displayNameSource: 'manual'` en Firestore.
- El cambio se refleja en tiempo real gracias al listener `onSnapshot` existente en `ChatWindow`.
- `ChatList` también refleja el cambio vía su propio listener de Firestore.

## Notas Técnicas

- El campo `displayName` es completamente opcional en el tipo `Conversation`; esto garantiza retrocompatibilidad con todas las conversaciones existentes en Firestore que no tienen este campo.
- El endpoint PATCH valida que `displayName` no supere 120 caracteres y no esté vacío.
- Se usó spread condicional `...(profileName ? { displayName, displayNameSource } : {})` en el webhook para no escribir `undefined` en Firestore (buena práctica con Firestore SDK).
- La lógica de resolución está centralizada en un helper `resolveDisplayName(conv)` en cada componente, facilitate futura unificación si se extrae a `lib/`.
