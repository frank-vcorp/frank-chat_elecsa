## Tarea(s) Abordada(s)

- Refactorización de la inyección de productos para Sofía para permitir un nivel de escalabilidad de hasta 12,500 productos.
- Implementación de la arquitectura de _Function Calling_ (Tool Calling) usando la API de Anthropic Claude.

## Cambios Realizados

- **`apps/web/src/lib/aiProvider.ts`**:
  - Se eliminó la función `getProductsCatalogText()` que descargaba recursivamente todo el catálogo e inflaba el Context Window del modelo en cada solicitud.
  - Se creó la función local auxiliar `searchProductsInDB(query)` con capacidades de búsqueda limitadas (máximo 5 resultados mostrados a la lA, con límite de lectura en Firestore de 200 documentos por transacción).
  - Se migró el prompt system principal en `callClaude` al formato nativo `tools` definiendo `buscar_productos_elecsa`.
  - Se implementó la lógica reflexiva: Si Claude dispara `tool_use`, se intercepta el resultado, se busca en la base de datos, se re-inyecta al Array de Mensajes de Anthropic con `tool_result` y se vuelve a lanzar la instrucción al LLM para generar la respuesta final natural para el cliente.

## Decisiones Técnicas

- **Claude 3.5 Haiku Function Calling**: En lugar de inyectar toda la carga útil en cada mensaje y gastar potencialmente cientos de miles de lecturas de BBDD al mes por interacciones irrelevantes, Sofía ahora solo consume Base de Datos _cuando el usuario orgánicamente solicita o pregunta por un producto o precio_.
- **Integridad de Lógica Previa**: Los saludos contextuales según la hora y comandos ocultos (SEMÁFOROS DE TESTING) se mantuvieron 100% operativos.
